# Domain Term Format

In this repository, definitions live in `PRODUCT.md` under Terminology.
Preserve the existing document and table format. `CONTEXT.md` stays technical;
never replace it with a glossary or create per-context documents automatically.

- Define only confirmed product-specific concepts, in one or two sentences.
- Pick a canonical term; note aliases to avoid when ambiguity matters.
- Explain relationships/cardinality where they change understanding.
- Resolve conflicting uses explicitly; keep unresolved meanings as open decisions.
- Use a brief example only when it clarifies a difficult distinction.
- Read template warnings; fictional examples are not project decisions.

Detailed observable behavior belongs in the relevant OpenSpec change/current
spec under `docs/openspec.md`, not duplicated in the glossary.
